Introduçao do Git e GitHub

O que é Git?

Git é um software que faz o controle de versoes. Ele faz o manejo dos repositórios locais (computador) e repositórios remotos (e.g. GitHub). Foi Criado por Linus Torvalds em 2005 para o gerenciamento do desenvolvimento do Kernel Linux. É um software livre e de acesso aberto.

O que é GitHub?

Já o GitHub é um dos repositórios remotos que sao possíveis de utilizar com o Git. É possível fazer a hospedagem dos códigos e acessar as versoes.

Como usar o GitHub com o RStudio?

Nessa sessao, vamos direcionar nossos esforços para entender como podemos usar o Git e o GitHub para ter um controle de versoes de nossos códigos desenvolvidos no RStudio.

Para isso, devemos conectar o RStudio com o GitHub. Faremos isso utilizando o pacote {usethis}.

Pacote {usethis}

O pacote {usethis} oferece algumas funçoes que possibilitam a configuraçao do RStudio para conectá-lo com o GitHub. Para isso, o primeiro passo é instalá-lo, caso ainda nao esteja instalado

install.packages("usethis")

Em seguida, vamos carregá-lo

library(usethis)

O primeiro passo é configurar o RStudio para utilizar o GitHub. Usamos o pacotte {usethis} para isso, usamos a funçao use_git_config():

usethis::use_git_config(
  user.name = "Alisson Dopona",
  user.email = "alissondopona@gmail.com"
)

Adicione o nome de usuário e email de acordo com a sua conta no GitHub. Para verificar se está configurado corretamente, utilizamos a funçao git_strep() para verificar se o nome e o email estao configurado corretamente.

usethis::git_sitrep()

Há um mecanismo de segurança implementado recentemente no GitHub que chama é o Personal Access Token (PAT). Ele é uma forma segura de acessar o GitHub e executar nossas atividades, sem precisar estar inserindo o nome do usuário e senha para todos as operaçoes. Nós podemos criar ele através de linha de comando ou através da interface do site github. Inserimos o nome do token e a data de expiraçao. Por questoes de segurança, nao é recomendado criar tokens sem data de expiraçao. No comando acima, podemos observar que o TOKEN ainda nao está configurado:

# • Personal access token for "https://github.com": <unset>

O primeiro passo entao é criar o Token. Nós podemos fazer isso diretamente na interface GitHub, ou entao, utilizar a funçao create_github_token() para direcionar a página do GitHub.

usethis::create_github_token()

Em seguida, devemos configurá-lo, e iremos fazer isso utilizando a funçao gitcreds_set():

gitcreds::gitcreds_set()

Em seguida, é de bom tom verificar se está conectado agora.

usethis::git_sitrep()

Podemos observar que agora temos o seguinte retorno:

# • Personal access token for "https://github.com": <discovered>

Isso significa que o deu certo a inserçao do token. É importante após a configuraçao do token, reiniciar a sessao do R em -> Session -> Restart R. Esse passo garante que o token foi internalizado.

Sendo assim, nosso RStudio está configurado com o GitHub e agora nossas operaçoes podem ser versionadas.

Segunda forma

Mas há uma forma adicional de fazer essa conexao. É através da criaçao de uma Variável de Ambiente que fica armazenado em um arquivo chamado .Renviron. Se esse arquivo nao existir, ele será criado no momento de rodar o código abaixo. Essa variável ambiente armazena o token, e o arquivo .Renviron permanece no computador. Por questoes de segurança, esse arquivo NUNCA deve ser armazenado no GitHub. Dessa forma podemos acessar, através da Variável de Ambiente, os tokens quando nessesário.

Dessa forma, se você tem um token para cada projeto, você pode armazenar esse arquivo na raiz do projeto, e adiciona o arquivo no .gitignore para que ele nao fique disponível no GitHub.

Para criar a variável, vamos utilizar a funçao edit_r_environ() também do pacote {usethis}. Ela irá abrir uma aba no RStudio do arquivo .Renrion, mostrando o local que ela está armazenada no seu dispositivo. No meu caso, está no diretório alisson do /home. Note que ela possui um . no início do nome, o que significa que é um arquivo oculto no diretório.

usethis::edit_r_environ()

Podemos fazer também através do terminal diretamente:

nano ~/.Renviron

Ao abrir o arquivo, indicamos o nome da variável e adicionamos o token nela. Por exemplo:

GITHUB_PAT=ADICIONAOTOKENAQUI

Salvamos esse arquivo e reiniciamos a sessao do R em -> Session -> Restart R.

Podemos verificar se funcionou com o comando:

Sys.getenv("GITHUB_PAT")

Pronto, se aparecer o seu token, significa que ele está configurado, e nao precisa fazer mais nada para para utilizá-lo no dia a dia.

No Rstudio, basta reiniciar o projeto para que possa fazer o comit pela IDE.

O que fazer após formatar a distribuiçao GNU/Linux?

Aqui, vamos demonstrar como reconfigurar o diretório local para estar sincronizado com o repositório na nuvem.

O primeiro passo, é configurar sua identidade no git e GitHub. Utilize seu use.name e email de acordo com aquele configurado no GitHub:

git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"

Em seguida, configuramos branches, para nao criar um paralelo (master) com o principal (main) utilizado pelo GitHub:

git config --global init.defaultBranch main

Confirmamos se foi configurado corretamente:

git config --global --get init.defaultBranch

Se retornou main entao significa que deu certo

Agora, vamos verificar o status do diretório via terminal para certificar a existência de um diretório .git:

ls -la

Caso haja o diretório .git significa que o histórico e configuraçao remota sobreviveram. Assim, basta verificar o remote e pull:

git remote -v
git status
git pull

Caso contrário (o mais provável) o ideal é reconectar via init + remote add, em vez de clonar por cima de arquivos já existentes:

No diretório do projeto, fazemos o comando git init:

git init

Em seguinda fazemos a clonagem:

git remote add origin https://github.com/seuusuario/repositorio.git

Depois:

git fetch

Em seguiga checamos se está tudo ok:

git checkout main

Por fim, garantimos o vínculo (tracking) entre o branch local e o remoto — isso é o que habilita Pull/Push corretamente no RStudio:

git push -u origin main

Verificaçao final:

git status
git branch -vv

O resultado esperado é nothing to commit, working tree clean e [origin/main] ao lado do branch no branch -vv.

Em uma situaçao em que há um curso ou disciplina que o material fica todo disponível em um repositório GitHub, como manejar?

Algumas vezes, participamos de disciplinas ou cursos em que o material fica todo disponibilizado em um repositório no GitHub. Nesse caso, há algumas questoes que precisam ser manejadas com cuidado para que nao perca conteúdo quando o professor atualizar o repositório, e que possamos fazer nossas modificaçoes.

O primeiro passo, é fazer o fork no repositório. Com o fork feito, vamos seguir fazendo a clonagem do nosso fork no terminal do nosso diretório:

git clone https://github.com/SEU-USUARIO/nome-do-repo.git
cd nome-do-repo

Em seguida, precisamos adicionar o repositório do professor (ou quem estiver ministrando a disciplina) como upstream. Esse passo é importante para que possamos receber as atualizaçoes do professor. Entao adicionamos o repositório do professor como upstream:

git remote add upstream https://github.com/PROFESSOR/nome-do-repo.git

Em seguida, seguimos com a verificaçao:

git remote -v

O resultado deve ser algo assim:

origin    https://github.com/SEU-USUARIO/nome-do-repo.git (fetch)
origin    https://github.com/SEU-USUARIO/nome-do-repo.git (push)
upstream  https://github.com/PROFESSOR/nome-do-repo.git (fetch)
upstream  https://github.com/PROFESSOR/nome-do-repo.git (push)

Quando o profesor avisar que houve atualizaçao do repositório, usamos os seguinte comando:

git fetch upstream

E

git merge upstream/main

O main significa em que local está o repositório. Podemos substituir se estiver em master.

Esses passos trazem as mudanças do professor para o branch local, mesclando com o que já temos no nosso repositório, sem apagar nossos arquivos.

Por último, para que possamos manter nosso repositório no GitHub atualizado com nossas alteraçoes locais, usamos os seguinte comandos para subir essas alteraçoes:

git add .
git commit -m "minhas atividades"
git push origin main

Dessa forma, as alteraçoes vao diretamente para o fork, sem precisar de pull request.

Há, porém, uma questao importante. Quando há uma alteraçao no mesmo arquivo dos dois lados (professor e aluno) poderá ocorrer conflito. Uma dica é manter as atividades em diretório separado.
